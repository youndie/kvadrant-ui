# Android device runs

Generated by `make android`. **Newest first, and nothing here is written by hand** — a row is added
by a run that passed, so a row is evidence rather than an intention. A run that fails records
nothing, which is what makes the absence of a row mean something.

Why this file exists is in `scripts/android_guard.py`'s docstring, and the short version is that
`connectedAndroidDeviceTest` is outside `check` for a good reason
([B-29](backlog/B-29-android-screenshot-coverage.md)) and was therefore invisible for months
([B-36](backlog/B-36-the-on-device-guard-does-not-execute.md)) — long enough for the Android artefact
to ship with no fonts in it at all
([B-37](backlog/B-37-the-android-artefact-ships-without-its-fonts.md)) with nothing saying so.

**A number measured on one Android version is a claim about that version**, which is why the API
level is a column rather than a footnote.

**The camera probe's reading is a column and not a verdict.** B-29 decided Android gets a *number*
where the desktop gets goldens, and until this file the number was solved, compared against a six per
cent window and thrown away — two runs a year apart on two Android versions were indistinguishable as
long as both passed. `solved` is the camera depth in pixels recovered from the drawn trapezoid,
`declared` is what the library asked for at that density.
