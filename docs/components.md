# Component catalogue

Everything `kvadrant-core` exposes as a composable, what it is, and where to press it.

**The table below is generated** — from the sources of the core and from the preview registry as the
compiler built it, by [`scripts/component_catalog.py`](../scripts/component_catalog.py). Editing it
by hand is undone on the next run, and `make check` fails when it is stale. The prose around it is
hand-written and is the part worth reading.

## How to read a row

- **Component** — the public composable, spelled as it is declared. `Kvadrant` is in every
  identifier this library exports; `Metro` appears only in prose, for the reason
  [research D4](research/research-architecture.md) gives.
- **Preview** — the id of a bare, running instance on the documentation site. A dash means the
  component has no preview of its own, which is not automatically a gap: `KvadrantTheme` is a
  wrapper and has no appearance to show. The count under the table is the honest version of that
  column.
- **What it is** — the first sentence of the component's own KDoc. The rest of that KDoc is the
  interesting half — which Microsoft template the component was transcribed from, and which numbers
  came from nowhere — and it is not duplicated here. Read it at the path in the next column, or on
  the component's page.

## Where the numbers come from

Every component in this list was built from a document rather than from a screenshot, and its KDoc
names which one. Four sources, in descending order of authority:

1. **`System.Windows.xaml` from the Windows Phone SDK** — the design-time template dictionary. This
   is what a control *was*, and it settled several things that had been guessed: that a text box is
   a light field in both themes, that focus does not bring in the accent, that a button's border
   sits inside twelve pixels of invisible touch target.
2. **`ThemeResources.xaml`** — the colours and the type ramp, which is where
   [`KvadrantTokens.kt`](../kvadrant-core/src/commonMain/kotlin/io/github/youndie/kvadrant/theme/KvadrantTokens.kt)
   is generated from.
3. **Microsoft's published UX guidelines** — the numbers that exist only as prose in a PDF.
4. **Nothing at all.** Eight metrics have no public source; the Pivot's were recovered by reverse
   engineering ([B-02](backlog/B-02-spike-pivot-metrics.md)). A number that is not Microsoft's says
   so in its KDoc and ships as a *parameter* rather than as a constant, so that a caller who knows
   better can say so.

Anything the phone did **not** do sits behind `KvadrantTheme(remastered = true)`, which is off by
default. That is what keeps the fidelity claim falsifiable: with it off, a component that looks
nicer than Windows Phone is a defect rather than a feature.

## Adding a component

1. Write it in `kvadrant-core`, from a document, and say in the KDoc which one.
2. Add a preview to `kvadrant-previews` — bare, the component and nothing else.
3. `./gradlew :kvadrant-previews:previewIndex && python3 scripts/component_catalog.py`.
4. `./gradlew check` — the ABI dump moves, and a reviewer has to approve the diff.
